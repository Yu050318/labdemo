## 1. 范围与完成定义

### 1.1 P0 范围

- Supabase Auth、个人空间、SSR 会话和账户生命周期。
- 双用户跨账户隔离及所有暴露表、查询、RPC、Route Handler 的 RLS 正向/负向。
- 日程、任务、方案与不可变方案版本。
- 准备清单、实验步骤、跳过、计时器和 revision 事务。
- 完成、撤销、再次完成及不可变 completion/归档。
- 站内通知、Push 能力检测及不可用降级。
- IANA 时区、DST、跨午夜、早/中/晚边界和晚间汇总。
- 当天+次日缓存、8 小时离线目标、24 小时 outbox、幂等重放和跨设备冲突。
- JSON/CSV 导出、软删除范围、永久删除排除和跨用户越权。
- G3 视觉、1440×900、390×844、320×844、原生 200%、键盘、焦点、语义和代表性对比度回归。

### 1.2 排除

P1/P2 继续排除，包括文档处理、AI、联网检索、材料库存、仪器预约、Worker、Docker 和团队功能。

### 1.3 G4 完成定义

- 每个实现增量均有唯一 commit、迁移版本、环境和可复现测试数据。
- AC-P0-01～12 相关实现均已执行正向、负向、异常和回归测试。
- 所有 S0/S1 缺陷关闭；S2 遗留必须由产品部书面接受。
- RLS 双用户负向测试、revision/幂等/事务、离线冲突、完成快照和导出越权均有数据库或 HTTP 证据。
- G3 视觉和可访问性回归无阻断。
- 未测试、被阻塞或仅有规格/单元测试证据的项目明确标注，不计为通过。

## 2. 每轮交付进入条件

开发部每个 G4 可测试交付必须提供：

1. 精确 commit、分支、构建命令和启动方式。
2. 增量范围、受影响 AC、RPC/Route/表和已知限制。
3. Supabase 环境类型、项目标识、migration 文件/版本及回滚说明；不得在报告中提供 secret 值。
4. 可重置的测试数据或 seed：
   - 用户 A：已验证、完整个人空间；
   - 用户 B：已验证、独立个人空间；
   - 未验证用户；
   - 找回密码用户；
   - 账户待删除用户。
5. RLS 正向/负向、事务、幂等和 revision 的开发自检结果。
6. 对应页面入口、API/RPC 调用方式及最短重置步骤。
7. 若涉及时间或离线：可控时钟/时区方法、outbox/IndexedDB 清理方法和冲突构造方法。
8. 若涉及 Push：不得提供私钥；提供能力状态切换和站内通知查询入口。

任一关键输入缺失时，只执行可独立验证的部分，其余记为阻塞，不推定通过。

## 4. 高风险专项矩阵

### 4.1 Auth、空间和 RLS

- 用户 A 对自身每类对象执行 select/insert/update/delete 和 RPC。
- 用户 B 使用已知 A 的 UUID、space_id、task_id、run_id、completion_id、export id 请求。
- 未登录、过期 JWT、已退出会话、未验证邮箱、账户待删除分别请求业务数据。
- Data API、RPC、Route Handler、导出和 Push subscription 均执行跨账户负向测试。
- 浏览器只持有 anon key 和用户会话；service role、Push 私钥和私有 helper 不得进入客户端、日志或错误。
- 用户 B 请求应为空或安全拒绝，不泄露对象是否存在、字段、正文或 revision。

### 4.2 事务、revision、幂等

- 创建命令不传 expected revision；单实体更新只比较一个实体 revision。
- 完成/撤销分别比较 task/run 或 completion 契约要求的 revision。
- 同一 mutation id + 同 payload 返回同一结果，不产生重复副作用。
- 同一 mutation id + 不同 payload 返回 `IDEMPOTENCY_KEY_REUSED`。
- stale entity revision 与父已完成分别登记 open conflict，reason 为 `STALE_ENTITY_REVISION` / `PARENT_COMPLETED`。
- 事务任一中间步骤失败时，业务对象、事件、receipt、revision 和归档均不得部分提交。

### 4.3 完成快照

- 第一次完成生成 completion A 和归档 A。
- 撤销只追加 `completion_undone`，A 保持只读。
- 再次完成生成 completion B 和归档 B，B 成为最新有效，A 仍可在历史查看。
- 重复完成、撤销非最新 completion、超过 30 天、活动计时器、必填步骤和 open conflict 均按契约阻断。

### 4.4 时间、离线和跨设备

- `Asia/Shanghai` 与至少一个 DST 跳时/重复时段 IANA 时区。
- 11:59/12:00、17:59/18:00、23:59/次日00:00、精确结束时间与无精确结束时间。
- 三个计时器跨两个实验；暂停、恢复、到点、跨午夜和设备时钟错误。
- 连续离线 7:59 可用、8:01 明确降级；待同步 23:59 正常、超过24h 不静默丢弃并持续提示。
- 两设备同实体旧 revision、不同实体并行、父完成后子 revision 仍匹配。

### 4.5 Push、汇总和导出

- Push 不支持、拒绝、订阅失效、投递失败、设备离线均保留站内通知。
- Push 成功不等同已读；失败不得删除站内通知。
- 晚间汇总按用户 IANA 时区生成；当日和次日均无任务时使用固定空文案。
- JSON 包含保留期内软删除对象及 `deleted_at`、`purge_after`、状态；CSV 排除软删除；永久删除均排除。
- 用户 B 不得通过参数、ID、缓存、下载 URL 或历史任务获得用户 A 的导出。

## 5. 每轮回归范围

### 5.1 固定冒烟

每个 G4 commit 至少执行：

- 当前增量单元/数据库/集成测试。
- TypeScript、lint、Next build；涉及部署适配时执行 OpenNext build。
- 未登录入口、登录后当前用户身份和跨用户基础拒绝。
- D01、W03、W04、C01 页面入口和控制台。
- 390×844、320×844 无横向溢出；代表性键盘焦点。

### 5.2 条件回归

- Auth/RLS 变更：全表、全 RPC、导出和 Push subscription 权限回归。
- 数据模型/RPC 变更：事务、revision、receipt、冲突、完成快照回归。
- 时间函数变更：DST、跨午夜、汇总、计时器、逾期全量回归。
- Service Worker/IndexedDB 变更：离线 8 小时、24 小时 outbox、升级缓存和跨设备回归。
- UI/CSS/布局变更：23 页面、10 状态、1440/390/320、原生 200% 和代表性可访问性回归。

## 6. 缺陷严重度与门禁

- S0 致命：跨账户泄露/写入、secret 暴露、不可恢复数据破坏、导出越权。
- S1 严重：核心闭环失败、事务部分提交、revision 静默覆盖、快照可变、outbox 静默丢失、关键操作在 320/200% 不可达。
- S2 一般：非核心状态或局部流程异常，有低风险绕行。
- S3 轻微：不影响理解、操作、数据和安全的视觉/文案问题。

每轮结论：

- **通过**：当轮范围全部执行，无 S0/S1，S2 已关闭或被产品书面接受。
- **有条件通过**：核心范围通过，仅有明确不影响当前增量的阻塞或已接受 S2。
- **拒绝/阻断**：存在 S0/S1，或关键权限/事务证据缺失。
- **待测**：可测试交付尚未到达；不是失败，也不是通过。
